# Customer Interviews: Research Ops Teams

Source type: three condensed interview transcripts with research operations leads at mid-market software companies.

Signal: Teams want a shared document workspace where subject-matter experts can edit source context without learning Git or YAML.

Signal: The strongest pain is not generation speed; it is confidence about which source material, prompt, and model produced a particular report.

Evidence: One research lead said, "We can get a draft quickly, but we cannot explain why last Thursday's draft differs from today's unless someone kept notes manually."

Evidence: Two teams already save generated reports in shared drives, but neither records prompt changes, model settings, or upstream document versions.

Concern: Non-technical reviewers are willing to edit Markdown-like notes, but they strongly dislike terminal workflows and configuration files.

Concern: Reviewers asked for a simple "needs update" indicator after source edits rather than a technical cache-state label.

Quote: "If I could update the background docs, press one button, and send the resulting brief, I would use that every week."

Open question: Do reviewers need real-time collaborative cursors, or is optimistic locking with a friendly conflict screen enough?
